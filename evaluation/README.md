# Rowflow AI Evaluation

Rowflow 서비스의 LLM 응답 품질을 검증한 테스트 코드, 평가 결과 및 비교 분석 자료입니다.

## 1. 평가 개요

- **최초 평가 범위:** 5개 기능, 기능별 8건(총 40건)
- **최종 서비스 범위:** 글쓰기 제안을 제외한 4개 기능(32건)
- **비교 모델:** GPT-4o mini, GPT-5.4, Claude Sonnet 5 (3종)
- **실험 조건:** GPT-4o mini 1차·2차 프롬프트, GPT-5.4 2차 프롬프트, Sonnet 5 2차 프롬프트(총 4개 조건)
- **평가 방식:** API 응답 수집 → GPT-4o mini를 이용한 LLM-as-a-Judge 예비 판정 → 사람 검토 및 필요 시 판정 수정

### 평가 기능

| 기능 | 사례 ID | 주요 평가 내용 | 최종 서비스 반영 |
|---|---|---|---|
| 소재 추출 | M01~M08 | 원문 충실성, 핵심 정보 추출, 주제 분류, 근거 문장 | 포함 |
| 후속 질문 | Q01~Q08 | 맥락 관련성, 단일 질문 여부, 사용자 답변 충실성 | 포함 |
| 글쓰기 제안 | S01~S08 | 소재 연결 타당성, 원문 충실성, 제안 방향 | **제외** (기존 실험 이력 보존) |
| 에세이 생성 | E01~E08 | 원문 충실성, 구성, 문체, 분량 | 포함 |
| 에세이 재생성 | R01~R08 | 사용자 수정 사항 반영, 원문 충실성, 문체, 분량 | 포함 |

평가 기준은 **모든 사례에 일괄 적용한 것이 아니라 각 사례의 목적과 특성에 따라 관련 지표만 선택적으로 적용**했습니다. 적용되지 않은 지표는 통과나 실패로 판정하지 않았습니다. **통과율의 분모는 사례 수나 지표 종류 수가 아닌 실제 평가 판정 건수**입니다.

## 2. 평가 진행 과정

1. **GPT-4o mini 1차:** 최초 40건으로 기능별 오류와 개선 필요 사항 파악
2. **GPT-4o mini 2차:** 프롬프트 개선 후 동일 사례 재검증
3. **추가 모델 비교:** 동일 사례·공통 평가 기준으로 GPT-5.4와 Claude Sonnet 5 평가
4. **서비스 범위 변경:** 글쓰기 제안 제외. 기존 5개 기능의 평가 기록은 보존하고, 최종 서비스용 통계는 4개 기능 기준으로 별도 재집계
5. **Sonnet 5 프롬프트 재평가(V3):** 원문 충실성 규칙과 사용자 요청 항목을 반영한 프롬프트로 에세이 생성·재생성 각 8건, 총 16건 재평가

## 3. 평가 결과

### 기존 4개 실험: 최종 서비스 4개 기능 기준

글쓰기 제안의 16개 평가 판정을 제외해 기존 실험을 **89개 공통 판정**으로 재집계한 결과입니다. 새로운 API 실행 결과가 아닙니다.

| 실험 조건 | 통과 / 판정 수 | 통과율 |
|---|---:|---:|
| GPT-4o mini 1차 | 63/89 | 70.8% |
| GPT-4o mini 2차 | 62/89 | 69.7% |
| GPT-5.4 (2차 프롬프트) | 64/89 | 71.9% |
| Claude Sonnet 5 (2차 프롬프트) | 69/89 | 77.5% |

초기 5개 기능 기준 전체 105개 판정 결과는 원본 평가 파일과 종합 보고서에 별도 보존했습니다.

### Sonnet 5 프롬프트 개선 재평가(V3)

| 기능 | 기존 Sonnet 5 (V2) | 수정 후 (V3) | 변화 |
|---|---:|---:|---:|
| 에세이 생성 | 22/31 (71.0%) | 21/31 (67.7%) | -3.2%p |
| 에세이 재생성 | 17/25 (68.0%) | 15/25 (60.0%) | -8.0%p |
| 생성 분량 준수 | 5/8 (62.5%) | 0/8 (0%) | -62.5%p |
| 재생성 분량 준수 | 2/5 (40.0%) | 0/5 (0%) | -40.0%p |

- V3 합계: **36/56개 판정 통과(64.3%)**. 생성·재생성의 동일 16개 사례와 공통 지표만 비교했습니다.
- 원문에 없는 행동·의도·감정 추가가 계속 관찰됐으며, 원문을 거의 그대로 반환하는 사례도 확인됐습니다.
- **사실 보존 제약과 분량 요구 사이의 충돌 가능성**을 확인했으나, 프롬프트가 분량 저하의 직접적인 원인이라고 단정할 수는 없습니다.
- 원문 충실성 등 정성적 지표는 자동 Judge 판정과 사람이 추가 발견한 문제를 구분하여 해석해야 합니다. 별도 정성 관찰을 기존 통과율 분모에 임의로 추가하지 않았습니다.

## 4. 평가 코드 및 결과 파일

| 위치 | 설명 |
|---|---|
| `material_runner.py`, `question_runner.py`, `proposal_runner.py` | 초기 평가의 소재 추출·후속 질문·글쓰기 제안 실행 코드 |
| `essay_runner.py`, `retouch_runner.py` | 에세이 생성·재생성 응답 수집 및 예비 평가 코드 |
| `*_cases.json` | 기능별 테스트 사례 및 평가 기준 |

| `reports/Rowflow_LLM_3모델_평가비교.xlsx` | 모델 비교, 서비스 범위 변경, Sonnet 5 V3 개선 전후 분석 |

실행 중 생성되는 중간 CSV·JSONL 파일과 최종 검수 완료 엑셀은 구분하여 관리합니다.

## 5. Opik 실험 기록

- **프로젝트:** `Rowflow-LLM-Evaluation`
- **데이터셋:** `Rowflow-Evaluation-40` (최초 40건 유지)
- **기존 실험:** `GPT4o-mini-V1`, `GPT4o-mini-V2`, `GPT5.4-V2`, `Sonnet5-V2`
- **추가 실험:** `Sonnet5-V3` — 에세이 생성·재생성 16건, 56개 판정

Opik에는 완료된 평가 판정을 업로드했습니다. 따라서 Opik 화면의 실행 시간·실행 비용 칼럼은 실제 모델 호출 성능 비교 자료로 해석하지 않습니다. 기존 실험을 덮어쓰지 않고 이력을 유지합니다.

## 6. 평가 방법 및 한계

- 통과율 = **통과 판정 수 / 실제 평가 판정 수 × 100**. 사례별 성공률이나 절대적 서비스 성능 지표가 아닙니다.
- **평가 지표의 선택적 적용:** 기능별 8건의 소규모 사례이며, 모든 사례에 모든 평가 지표를 적용하지 않았습니다. 각 사례에 실제 지정된 지표만 평가했습니다.
- **미평가 항목 해석:** 평가하지 않은 항목은 통과로 간주하지 않았으며, 해당 품질 문제가 없다는 의미도 아닙니다. 별도로 관찰된 오류는 정성적 관찰로 기록하되 기존 통과율의 분모·분자에 임의로 반영하지 않았습니다.
- **판정 수와 지표 수 구분:** 초기 105건, 최종 범위 89건, Sonnet 5 V3 56건은 평가 판정의 총건수이며 서로 다른 평가 지표의 개수가 아닙니다.
- LLM-as-a-Judge의 오판 가능성이 있어 사람 검토 및 오류 기록을 병행했습니다.
- 글쓰기 제안 제외 후 89개 판정 집계와 V3의 56개 판정 집계는 **범위가 다르므로 직접 비교하지 않습니다**.
- 사용자 추가 요청 항목의 효과는 원문 충실성 개선 실험과 구분하여 검토해야 합니다.

상세 집계 기준과 정성적 오류 유형은 `reports/Rowflow_LLM_3모델_평가비교.xlsx`를 참고하세요.

## 7. 후속 과제

원문 충실성과 분량 준수를 동시에 개선할 수 있도록 허용 가능한 서술 확장 범위, 정보 부족 시 처리 원칙을 검토합니다. 모델별 토큰 비용·응답 시간은 개발 단계의 별도 측정 결과와 함께 검토하며, 최종 모델 선정 시 품질·비용·속도를 종합적으로 고려합니다.
