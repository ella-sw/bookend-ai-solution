데이터 규칙

1. 버전 번호AI 처음 결과 = 초안(version_no 0). 이후 사용자가 저장할 때마다 v1, v2…. 직접 쓴 글은 첫 저장이 v1. 버전 하나를 지울 수 있다. 초안과 마지막 남은 버전은 지울 수 없다 (409 version_not_deletable). 번호는 다시 매기지 않는다. 새 버전 = max(version_no) + 1.
2. 원본 고정records.status = saved가 되면 본문을 바꿀 수 없다 (서버·DB 트리거에서 막음).
3. 분석 응답응답의 요청 번호가 records.latest_analysis_request_id와 같고, ai_requests.status = running이고, 요청 시작이 users.data_cleared_at 이후일 때만 저장. 60초가 지나면 timeout (expire_ai_requests, 매분).
4. 확인 대기original_kept_at이 없고 보관 확정된 소재가 없는 저장된 기록 중 analysis_status가 analyzing·done(보관 전 후보)·empty·failed인 것. M120 보관 전 화면 더보기와 M110 카드 [⋯]에서 기록 삭제(규칙 6).
5. 원본만 보관 목록original_kept_at이 있고 보관 확정된 소재가 없는 기록. 소재 없음 화면에서 [새로 기록하기]/[새 대화 시작하기]를 누르면 기존 기록에 original_kept_at을 기록한다.
6. 기록 삭제보관 확정된 소재가 없는 원본만. 실제 삭제: records·qna_messages·확정 전 materials·관련 ai_requests. events.record_id는 비움. 확정 소재가 있으면 409 material_confirmed, 삭제된 소재면 409 material_deleted.
7. 소재 삭제글에 쓴 소재(essay_materials 연결, 직접 쓰기 임시 저장 포함): deleted_at만 기록 (논리 삭제). 기존 글에는 '삭제된 소재'로 표시하고 원본은 남는다. 글에 쓰지 않은 소재: records 행을 지워 materials·material_topics·qna_messages·관련 ai_requests까지 실제 삭제. 응답 200 + record_deleted. v9: 확정 (B 1a6ff01, 목록 33번). 두 경우 모두 그 주제의 제안을 다시 계산하고, 삭제된 소재가 든 생성 요청은 막는다 (409 material_not_available / material_not_found).
8. 보관 확정materials.confirmed_at이 있어야 고르기·관련 추천·제안·사용 횟수에 들어간다.
9. 제안(user_id, topic_id)당 1개. 같은 주제에 서로 다른 기록의 보관 확정 소재가 suggest_min_records(3) 이상이면 계산. v9: 저장한 글(essays.status = saved)에 쓴 소재는 후보에서 빼고 남은 소재로 다시 계산한다. 임시 저장 글은 세지 않는다. 글을 저장·삭제하면 그 소재들의 주제를 다시 계산 (B 763fc1a, 목록 62번). basis_hash = 소재마다 (id + updated_at). 같으면 AI를 부르지 않음. 제안 AI가 direction을 만들어도 화면에 쓰지 않음. 제안 계산은 하루 한도(규칙 19)에서 뺀다 [확인 대기: 팀, 29번].
10. AI 질문첫 질문은 답변 필수, 바꿀 수 없음 (409 first_question_not_replaceable, 첫 답변 전에는 1/30·2/30…로 넘김). v9: 그날 공통 질문 30개의 순서는 그대로 두고, 이 사용자가 그날 이미 첫 질문으로 쓴 질문은 뒤로 보낸다 (C 63b51cd, 목록 63번). [소재로 저장]은 답변 2개부터. [다른 질문 보기] 대화당 6회 = is_replaced = true 행 수. 답변 7개가 차면 마무리.
11. 에세이 생성 입력고른 소재의 제목·요약·근거 + 원본(소재당 1,500자), 요청사항(essays.request, 선택 200자), 문체·길이. 다시 만들기는 지금 본문 + 삭제되지 않은 소재 + 처음 요청사항 + 문체·길이. v9: direction은 받아도 AI 입력에 넣지 않는다 (11/24). 보낸 내용을 generation_input에 그대로 남김.
12. 저장 중복·AI 결과같은 save_token은 한 번만 저장 (두 번째는 200 + 기존 결과). 다시 만든 결과를 저장하면 ai_requests.result를 비운다. 바탕 버전이 지워졌으면 404 version_not_found.
13. 글 제목essay_versions.title이 기준. essays.title은 최신 버전 제목의 사본. 버전을 지우면 남은 최신 버전 제목으로 다시 맞춘다.
14. 모든 기록 삭제events·essays(버전·연결)·suggestions(연결)·records(문답·소재·주제 연결)·ai_requests를 지우고 users.data_cleared_at 기록 (clear_user_data). users 행과 ai_consent_at, ai_usage는 남김.
15. 1달 정리last_seen_at 후 1달이 지나면 위와 같은 범위로 정리 (cleanup_inactive_users, 매일 UTC 19:00).
16. 임시 저장·진행 중records는 type별 draft 1개·active 1개 (부분 유일 인덱스). essays는 직접 쓰기 draft 1개. active = 진행 중 AI 문답, 1시간 지나면 지움. 이어 쓰기는 [임시 저장] 때 checkpoint를 남기고 되돌릴 때 그 뒤 행·AI 요청을 지움.
17. RLS모든 테이블은 user_id = auth.uid()인 행만 읽기·쓰기. 브라우저에서 테이블에 직접 접근하지 않고 API(app_user)로만. topics·daily_questions는 읽기만.
18. 상태 값 타입text + CHECK (B 구현으로 확정).
19. 하루 AI 한도ai_usage(user_id, day).calls. 기본 한도 50 (ai_daily_limit). v9: 시연 계정(demo_user_ids)은 500 (ai_daily_limit_demo, 목록 61번). 넘으면 429 daily_limit. 사용자 동작 1번 = 1회. 길이 자동 재요청·제안 계산은 세지 않음.
